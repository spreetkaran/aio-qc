Testing

Testing (formerly the Frame Extractor's Model Lab) measures and compares YOLO weights on your data. It is a tool of Image QC's Models tab (Ctrl+Alt+L), not of the Frame Extractor, and it never controls the player (6 · Review videos only hands a playlist over). It works in five steps, shown as a stepper across the top of the window. Each step shows a ✓, a warning or an error icon, and a bar under its title explains any problem with a button that fixes it.

Testing and Image QC

  • This dataset — the dataset open in Image QC is the default test data: its files, labels and classes, exactly as Image QC sees them. Opening another dataset in Image QC switches Testing to it.
  • Models — the dataset's models from Models & Environment are the default models, with their class maps (model class → dataset label). Add AIO QC's models offers every model added anywhere in the app; weights you add here are added to AIO QC's models too. One Python environment runs .pt / .engine models everywhere.
  • One prediction cache per dataset (.aio_qc/predictions.db): Model Check uses Testing's predictions of the same weights (same image size and SAHI setting) instead of running the model again.
  • Label fixes made in Testing's viewer go through AIO QC: the original is backed up (History ▸ revert, or Backups), the change is in the file's history, a flagged file becomes Fixed, and Image QC shows the new labels at once.
  • Leave out of scoring is stored with the dataset (.aio_qc/testing_excluded.json).
  • Send to review on the Failures and Compare A / B tabs flags those images in Image QC and filters its file list to them.
  • The project of the open dataset is part of its AIO QC session (.aio_qc/testing.fxlab) and comes back when Testing opens on it; any other .fxlab (also from the standalone FrameExtractor) still opens with Project ▸ Open.

Projects

A project (.fxlab) remembers the whole set-up — test data, videos, models and their colours, run options and report settings. The start page (⌂ Projects) lists recent projects with their best model and score; reopening one shows its results again in seconds, because predictions are cached. The open session is saved automatically, so closing the window never loses work. Project ▸ New (Ctrl+N), Open (Ctrl+O), Save (Ctrl+S).

Drag and drop — drop weights, videos, image folders, a data.yaml or an .fxlab file anywhere on the window; each goes where it belongs.

Labels

Labels are optional. To measure true accuracy: Pre-label with a model → open the folder in your labelling tool and fix the boxes → the files you edit count as ground truth automatically. Mark pre-labels reviewed accepts the rest. Until then, unreviewed pre-labels are left out of scoring — otherwise a model would be scored against its own predictions.

Videos for behaviour analysis

Each model also runs over whole videos (a frame every N seconds) to show how it behaves where nobody has labelled anything: detections over time, flicker (an object disappears for a frame or two), blips (an object seen for one or two samples), agreement between models, and the moments they disagree most. Long videos stay fast: at most 20,000 samples are taken per video (the interval grows automatically), and frames far apart are reached by seeking rather than decoding everything — an hour of video with two models takes about a minute, and is instant from the cache afterwards.

2 · Models

Add any number of weights (.pt, .onnx, .engine). Each keeps its colour in every chart, image, report and annotated video. Classes are matched to the test data by name, so models trained with different class orders compare correctly; Check models shows the match and any classes that will be ignored.

3 · Run

Every model runs on every image in batches. Predictions are cached: stop at any time and continue later; a model already run on these images costs nothing, even after you rename its file.

  • Ground truth — labels, or (with no labels) a reference model: the others are scored on how closely they reproduce it. This compares a candidate with the model in production; it is not true accuracy.
  • Confidence threshold — best F1 per model (the fair way to compare) or one fixed value.

Videos only

With No images - videos only, the frames sampled from your videos fill every tab (up to 6,000 frames, spread evenly over all videos). With two or more models and a reference model chosen on the Run page, the others are scored against it: Overview, Charts, Confusion matrix, Per class and Failures show where each one disagrees with the reference, and Compare A / B shows a model next to the reference (what it misses, what it finds that the reference does not). This is agreement, not true accuracy. With one model, or no reference, the tabs that need an answer key say so, and Plots and Videos still show everything.

The threshold control at the top updates the error counts, confusion matrices and galleries live. Results are calculated in the background and only for the tab you are looking at, so the window stays responsive with large test sets.

Click a chart to see the images

Click a confusion-matrix cell, a class bar or an error-type bar and the Failures tab opens filtered to exactly those images (for example person predicted as car). The filter shows as a chip at the top — ✕ Clear filter removes it. Clicking a moment on a video timeline shows that frame plotted.

Fix labels on the spot

When a “failure” is really a labelling mistake, double-click it in Failures (or right-click ▸ Fix labels…) and correct it: delete a box (Del), change its class, draw a missing box, or accept a detection as ground truth. Leave this image out of scoring excludes a bad image without touching the dataset. Changes are saved to the label files (YOLO lines and LabelMe shapes keep everything else they contain) and the scores update at once.

A / B viewer

Plotted images and chart labels use the Inter typeface; the rest of the window uses the app's font. Saved plots look exactly like what you see, and annotated videos use the same labels.

Side by side… on the Compare tab (or right-click a failure ▸ Compare with another model…) shows the same image for two models side by side. Zoom and pan are linked; toggle ground truth, use each model's own threshold or one fixed value, and step through the images with the arrow keys. Save image… saves both plots side by side.

5 · Report

One HTML file with every chart, table and image inside — it opens in any browser, supports light and dark, and prints well. Summary is one page for a decision; Detailed has everything; Comparison puts two models head to head; Video behaviour covers the label-free analysis. metrics.json, per_class.csv and per_image.csv are written next to it for your own analysis. Export annotated video draws up to four models on a video.

Tip — to analyse a video you are watching in the Frame Extractor, add the same file under Videos for behaviour analysis (with a time range such as 1:00-4:30 to limit it).

6 · Review videos

Watch the models at work on whole videos: Review in player plays the videos one after another in the Frame Extractor with every model's boxes drawn on the video. Testing only sends the playlist (videos, models, settings) - the player does the rest and never interferes with Testing.

  • Videos - Add videos…, Add folder…, or Use step 1's videos. Double-click In / Out to play only part of a video (1:30, 90). ↑ ↓ set the order.
  • Models - the models of step 2, each with its colour and a card: format, size, input size, task, batch, number of classes and their names. A .pt file new to the app is flagged (it can run code when loaded); an .engine runs only on the GPU / TensorRT it was built for.
  • Analysis - Balanced (recommended): smooth real-time playback. When the models keep up, every frame gets its own detections live. When they can't (CPU only, large models, SAHI, many models, 60 fps 4K), the frame step adapts so playback never stalls, the frames in between are interpolated from the analysed frames on both sides, and spare time fills them in afterwards - replay, seek or pause and every frame has its own detections. Best quality: every frame; playback briefly waits when needed, like video buffering. Fixed step: every N-th frame. Look-ahead is how far ahead detections are kept ready; Show boxes from confidence is the starting threshold. The defaults are in Settings ▸ Video review.

In the player, the Review playlist panel shows each video's state, what the analysis is doing ("every frame", "every 2nd frame + interpolated · backfilling 63 %", "4.2 s ahead"), Previous / Next, Loop, a switch per model and a live confidence slider (nothing is re-run). A paused frame always gets its own detections. Boxes on frames the models did not see themselves (interpolated) are dashed. Frames are decoded on the CPU with the player's own decoder, so the boxes belong to the exact frame on screen - with the built-in engine and with libmpv. Detections are saved in the prediction cache: a second review, Testing's video analysis and the annotated export reuse them.

Over time. A strip under the seek bar shows each model's detections per frame (one lane per model, grey where nothing is analysed yet) with the events as coloured ticks: models disagree (a box of one model has no same-class box of another), flicker (a model loses an object for one frame) and uncertain (a box just below the threshold). Classes are compared by name, so models with different class orders compare correctly. Click the strip to seek; the event list and Alt+[ / Alt+] jump between events. Classes hides classes in the player; CSV… saves every detection of the video.

Send hard frames to Image QC… picks the frames worth labelling - where the models disagree, flicker or hesitate, strongest first and spread out (at most N per video, at least S seconds apart) - saves them in the output folder with LabelMe pre-labels from the model you choose, remembers each frame's video (Image QC ▸ Show Source Video) and opens them in Image QC: from a review to the next training round in one step. End review (or the end of the playlist) brings back the video that was open before, at its frame; opening another video by hand ends the review too.
