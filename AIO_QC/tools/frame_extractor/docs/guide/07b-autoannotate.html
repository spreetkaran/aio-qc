Auto-Annotate

Ctrl+Shift+U (also in Image QC ▸ Tools) turns a folder of videos into unique frames with a LabelMe file each, drawn by your model — in five steps. Tick the steps you want and press Run; every page also has Run only this step.

StepWhat it doesWhere the result goes
1 FramesEvery Nth frame, or the sharpest of every N; skips repeats within a video as it is decoded (and, if ticked, frames already taken from another video or an earlier run); optional blur filter. With Images instead of Videos, an image folder is linked in (no extra disk space; your folder is never changed).frames/<video>/
2 Similar framesCompares every frame with all frames kept so far — across videos too — and sets aside the ones that look the same (strict / balanced / loose); of two similar frames the sharper can be kept. similar/
3 AnnotateYour trained model or AI annotate (below). Your model (.onnx here, .pt in your Python environment) writes one LabelMe and/or YOLO file next to every frame. Its classes and image size are read from the model file. Confidence, IoU, max boxes, smallest box, a minimum confidence per class, renaming or leaving out classes. LabelMe 6.3.1 or 5.11.4; imageData off by default; YOLO .txt files optional.next to the frames
4 Keep ruleKeep a frame when it has at least one / all of the classes you choose, any box at all, or always. Other frames (with their files) are moved, or kept.extra_images/
5 PackageOne folder, a folder per video, or folders named by a pattern in the file name; parts of N frames (part_001 or part_0, part_200), each zipped. Files as hard links (no extra disk space; the default) or as copies (independent of frames/). package/ + parts.csv

AI annotate

Annotate ▸ Who annotates ▸ AI annotate: no trained model — describe the classes in plain words, add a few examples, and a vision model annotates. Everything is set in the app; the project is saved as a config.yaml (Export… to share it or run it with --ai-config).

  • Is everything ready? comes first: the app, the Python environment (for models on your computer: PyTorch, transformers …, with an Install button), the API key and the AI service. A missing key is asked once and saved as the environment variable the project names (Windows: your user environment variables; macOS/Linux: your shell profile) — never in the project file, a log or a report.
  • New… starts from a template (find objects · detector + check · read text with its parts · look inside a bigger object · yes/no questions) or an example project.
  • 1 Connect LiteLLM, OpenAI, Azure, Gemini, Claude, Bedrock, OpenRouter, Qwen (DashScope), Together, Groq, Mistral, xAI, vLLM, Ollama, LM Studio, any OpenAI-compatible address, or a model in your Python environment · 2 Model the model (List models), what the AI does, the detector, polygons (SAM), advanced settings · 3 Classes names in YOLO order, plain-word descriptions, min confidence, at most per image, inside another class, read text with a pattern and a check digit (ISO 6346 / Luhn), parts · 4 Examples per camera, with their boxes (draw them in the app) · 5 Checks extra answers and rules to keep an image, look only inside a class, budget, targets, prices · 6 Output YOLO txt (default) / LabelMe / both, data.yaml, review flag · 7 Try a few images with the boxes next to the AI's answer, and an estimate for the whole run.
  • Answers are cached: Try again, re-runs and Stop/continue never pay twice. Rejected images go to rejected/ with reports/rejected.csv; every answer is kept in reports/ai_audit.jsonl.
  • The box format of the model (Gemini 0–1000 [y,x,y,x], Qwen pixels, …) is set from its family; Detect… asks the model to box an example whose boxes are known and keeps the format that fits.

Stop and continue

  • Stop is always safe. Run continues: extraction from its checkpoints, annotation from the files already written.
  • Running a step again first puts back what that step and the later ones set aside, so a new threshold or rule applies to the whole set again.
  • Annotation files the run did not write, and files you edited after it wrote them, are never overwritten (unless Existing files ▸ Replace).
  • Changing the frame settings asks before replacing the previous frames. Your videos are never touched — only the run folder.

Try it first

Try on 4 frames (Annotate page) runs the model with the current settings on a few frames and shows the boxes and whether the keep rule would keep each frame. Nothing is written.

Setups

Save keeps every choice under a name (the project); pick it next time and only the video folder changes. More ▸ Command line for this setup copies the same run as a command, e.g. for a GPU server:

aio-qc autoannotate D:/runs/batch_12 --videos D:/videos/batch_12 --setup project.aasetup.json
aio-qc autoannotate D:/runs/batch_12 --only annotate,rules --conf 0.4     # again, on the frames already there
aio-qc autoannotate D:/runs/batch_12 --status

The run folder

frames/ (the working set) · similar/ · extra_images/ · package/ · reports/summary.html (what every step did) · .autoannotate/ (the run's own records). Open in Image QC reviews the frames and their annotations.
