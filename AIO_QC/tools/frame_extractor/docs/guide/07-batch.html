Batch extraction

Ctrl+B opens the queue. Add videos (or drop several files on the main window); each row can have its own start, end and ROI. Videos are processed in parallel worker processes; long videos are split across workers when there are fewer videos than workers.

What gets saved

SettingEffect
SamplingEvery N-th frame, or the sharpest frame of every window of N frames.
Min sharpnessSkip blurry frames (Laplacian variance; the status bar shows the current frame's value — right-click the timeline strip to take it from the current frame).
Blurry negativesKeep 1 of every K rejected blurry frames in a separate folder (useful as negatives).

Mining with models

With models configured (Settings ▸ Models), the batch can keep only the frames worth annotating. A frame is kept if it matches any checked criterion; no criteria = keep all.

Pre-annotations — write LabelMe JSON or YOLO txt next to every saved frame from the model's detections, ready to correct in your labelling tool.

Speed and robustness

  • Parallel workers and Use of this PC — Auto plans workers from your CPU, memory and current load so the PC stays usable.
  • Resume interrupted jobs — a stopped, crashed or cancelled batch continues where it stopped.
  • Presets — save and load all batch settings; the command line reads the same preset files.

Reviewing the results

Ctrl+G opens the review gallery for an output folder: frames, blurry negatives and rejected images, filtered by mining reason, with pre-annotations drawn. Reject moves an image and its label file into _rejected/ — Restore or Ctrl+Z undoes it. Rejected frames stay in the hash database, so they are not extracted again.
